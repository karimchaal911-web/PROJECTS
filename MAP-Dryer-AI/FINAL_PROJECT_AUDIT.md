# Final project audit

Last repository-wide pass before the MAP Dryer AI project is archived and
presented. Scope: inventory, classification, junk and duplicate removal,
notebook QA, encoding and unit checks, dependency and path audit, runtime
validation, and a safe commit to the existing GitHub repository.

Nothing in the modelling methodology, the datasets, the reported metrics, the
Power BI report or the report/presentation content was redesigned. The changes
are cleanup, correctness and reproducibility fixes.

matplotlib's per-glyph fallback while keeping Arial as the primary face. After
re-execution there are **zero** missing-glyph warnings.

## Reproducibility defects found and fixed

Two defects meant the shipped repository could not actually be reproduced from
a clone. Both are fixed.

### 1. The hash-verified artifacts could not survive a checkout

`validate_runtime_contract()` compares the SHA-256 of the model and audit JSON
files against the values recorded inside them. With `core.autocrlf=true` and no
`.gitattributes`, Git stored those files with LF and restored them with CRLF, so
their bytes — and therefore their hashes — differed between the working tree and
any fresh clone. The working-tree copy of `models/5s/reference_profile.json`
also differed from its own blob by two bytes.

A `MAP-Dryer-AI/.gitattributes` now marks the hash-verified artifacts `-text`,
and they were re-added so the stored blob equals the working-tree bytes exactly.
Verified for all seven contract files:

```
MATCH  models/5s/feature_schema.json          blob=8618  disk=8618
MATCH  models/5s/reference_profile.json       blob=12225 disk=12225
MATCH  models/5s/training_report.json         blob=10058 disk=10058
MATCH  models/model_registry.json             blob=2089  disk=2089
MATCH  models/prototype_manifest.json         blob=1551  disk=1551
MATCH  artifacts/notebook03_model_evaluation.json  blob=5394 disk=5394
MATCH  artifacts/notebook04_anomaly_evaluation.json blob=2632 disk=2632
```

The same file also pins `*.ps1` to CRLF for Windows PowerShell 5.1 and marks
the binary deliverables.

### 2. The test suite failed on a fresh clone

`data/processed/MAP_Dryer_TEST_Replay_5s.csv` (37 MB) is deliberately git-ignored
as heavyweight local data, but two tests in `tests/test_canonical_pipeline.py`
required it and reported a red suite on any clone. Both are now guarded with
`unittest.skipUnless`, naming the missing file and how to regenerate it. Locally
the suite is unchanged at 77 passed; on a clone it is 75 passed, 2 skipped
instead of 2 failed. No assertion was weakened and no test was removed.

### 3. The notebook sequence could not complete

Notebook 03 rewrites `models/5s/reference_profile.json`, but the integrity
record for that file is issued by Notebook 04 — and Notebook 04 validates it in
cell 56, *before* the cell that re-issues it. Running 01 → 04 therefore always
failed at cell 56 with `reference_profile_hash_matches: False`. The pair was
reconciled by running `train_anomaly_and_diagnosis()` once, after which the full
sequence completes cleanly. The ordering constraint is now stated in the README
so the four notebooks are run as a set.

## Other corrections

* **`run_final_demo.ps1` → `RUN_FINAL_DEMO.ps1`.** Every one of the fifteen
  references in the README, the dashboard README, the demo instructions and the
  script's own header used the uppercase name, and the sibling launcher is
  `RUN_PRESENTATION.ps1`. The lowercase filename was the outlier and would have
  broken on any case-sensitive checkout.
* **Dependencies.** `requirements.txt` was missing `joblib`, `nbconvert`,
  `psycopg[binary]`, `python-dotenv` and `pytest` — the last of which the README
  tells the reader to run. `realtime_pipeline/requirements.txt` began with a
  stray `# Add pandas` comment and then did not list `pandas`, which the service
  imports. Both files now match what the code actually imports; the unused
  `openpyxl` was dropped after confirming no `read_excel` call or `.xlsx` file
  remains.
* **`.env.example`** was rewritten to separate the supported five-second service
  from the legacy one-minute block, to document that `MOISTURE_MODEL` is written
  by Notebook 03, and to add `ENABLE_LEGACY_1MIN_REPLAY`.
* **Legacy replay guard implemented.** `FINAL_TECHNICAL_QA_2026-08-08.md` states
  that `replay_service.py` was "guarded behind explicit
  `ENABLE_LEGACY_1MIN_REPLAY=true`" after it silently corrupted the dashboard
  with 127 incompatible one-minute rows. The guard was not in the code. It now
  is, matching the documented behaviour exactly.
* **`.gitignore`** dropped three whitelist rules for prototype datasets that no
  longer exist, and gained the LaTeX intermediates, `.pytest_cache/` and the
  entries needed to version the handoff and the three runtime artifacts.
* **Encoding.** Every text file in the project is valid UTF-8 with no U+FFFD
  characters. UTF-8 BOMs were stripped from four Python files; the BOM on
  `RUN_FINAL_DEMO.ps1` was deliberately kept, since Windows PowerShell 5.1
  needs it.
* **Broken document paths.** `design/RESOURCE_AUDIT.md` cited
  `branding/ocp.png`, which does not exist; it now points at
  `assets/original/ocp.png`.
* **README** gained the automated notebook runner, a final-deliverables table,
  the notebook ordering constraint, and a repository map that includes
  `final_presentation_claude/`, `resources/`, `tools/`, `conftest.py` and
  `.gitattributes`.

## Remaining known limitations

1. **Power BI and PostgreSQL were not exercised live.** See "Not tested" above.
2. **`FINAL_TECHNICAL_QA_2026-08-08.md` cites `tests/test_realtime_service.py`**
   ("circular-history cadence/wrap tests"). No such file exists and no
   equivalent test was found elsewhere. The dated record was left as written
   rather than edited, and no test was fabricated to make it true.
3. **The same document cites `artifacts/final_preview_page1_v2.png` and
   `page2_v2.png`.** Git history shows they were never committed. The current
   equivalents are `POWERBI DASHBOARD/preview/preview_page{1,2}_*.png`.
4. **`RUN_FINAL_DEMO.ps1` sets `CONTINUOUS_DEMO_MODE`, which no Python code
   reads.** The looping behaviour the QA document attributes to it is actually
   controlled by `MAX_CYCLES` and `EXIT_WHEN_EXHAUSTED`, both of which work. The
   line is vestigial, not harmful, and was left alone.
5. **`resources/presentation_resources/screenshots/siteassist/siteassist_reference_02.png`
   and `_03.png` are byte-identical.** Both are tracked source references and
   neither is cited individually, so both were kept rather than guess which name
   is intended.
6. **`MAP_Dryer_Dashboard_Demo_Audit.json` is a dated build record** from
   2026-08-28. Its `protected_hashes_after` block lists notebook hashes that
   predate this audit's re-execution. Nothing verifies it at runtime; it is
   provenance for that build, not a live contract.
7. **Two 235 MB canonical CSVs are byte-identical duplicates** on disk. Both
   paths are referenced by code, so both were kept. They are git-ignored and do
   not affect the repository.
8. **`final_presentation_claude/web/node_modules/` (391 MB) was kept.** It is
   git-ignored and restorable from `package-lock.json`, but removing it would
   break the offline presentation build on this machine before the defence.
9. **Windows long-path limit.** Cloning into a deeply nested directory fails on
   `POWERBI DASHBOARD/MAP Dryer AI Dashboard.Report/StaticResources/…`. From a
   normal location the path fits; from a long one, `git config --global
   core.longpaths true` is required. This is a Windows constraint, not a
   repository defect, and the Power BI folder names are fixed by the PBIP format.
10. **Large blobs remain in Git history** from earlier commits. Removing them
   would require rewriting published history, which this audit deliberately did
   not do.
