# GENERATIVE AND 3D ASSET PIPELINE — DECISIONS

This directory exists because the brief asked for a Higgsfield cinematic-asset
studio and a Blender asset workshop. Both were evaluated against the actual
needs of this presentation. **Neither is used in the shipped build**, and this
document records why, because "we chose not to" is a design decision that has to
be defensible rather than silent.

---

## 1. Higgsfield — evaluated, not used

### What it was considered for
Establishing plates for scene 01, an aerial industrial visual for the OCP
context beat, atmospheric background footage, and a hero dryer plate.

### Why it was rejected

**The project already owns better material.** `assets/process/` contains four
real photographs from the actual site: the rotary dryer shell with its riding
rings, the drying-section structure with its green painted steel, downstream
solids transfer, and the real product in storage labelled *MAP Monoammonium
Phosphate 12-61-00*. A generated industrial plate would be a plausible-looking
building that is not this building.

**The engineering-truth rule forbids it where it matters most.** The brief's own
constraint is that generative imagery must not be used when real project images
are stronger or when equipment accuracy would be compromised. For the dryer —
the hero object of the entire film — accuracy *is* the argument. A generated
rotary dryer would be an invented machine standing in for a real one in a
presentation whose central claim is that everything shown is verifiable.

**The one place it could have helped is the place it would have hurt.** Scene 01
wants an establishing shot at plant scale. But scene 01 must rhyme exactly with
scene 14 — same camera, same light, same machine — and that rhyme only works if
both are the same live 3D world. A generated plate in scene 01 would break the
film's closing move.

### What was done instead
The real photographs drove the procedural model and the material palette
directly. The key art-direction finding of the whole project came out of one of
them: the plant's structural steel is painted green, so the OCP identity and the
industrial reality are the same palette and the world can be brand-grounded and
photo-grounded at once. That insight is worth more than any generated plate.

### If it were revisited
`prompts/` holds the shot briefs that were written before the decision, kept so
the reasoning is auditable. They are specified to the level the brief requires —
reference, engineering constraint, narrative purpose, camera, lens, lighting,
movement, forbidden changes — and could be executed as-is.

## 2. Blender — evaluated, not used

### Why
Every form in this world is a lathe, cylinder, torus, box, extrusion or
instanced primitive. There is no organic geometry, no character, no baked
animation and no scanned asset. A Blender round-trip would add a binary asset
pipeline — GLB export, Draco decoding, KTX2 transcoding — with nothing to show
for it.

### What that buys the soutenance
The entire presentation is a text repository. It runs offline with no binary
model to fail to load, no decoder to fail to initialise on unfamiliar
presentation hardware, and no asset-version drift between the design documents
and the build. For a one-shot live presentation on a machine you do not control,
that reliability is worth more than the fidelity Blender would have added.

The full geometry budget is in `design/THREEJS_SCENE_PLAN.md` §4: about 62 k
triangles and 55 draw calls for the whole world.

### If it were revisited
The candidates, in order of payoff:

1. **Girth gear and drive train** — currently 96 instanced boxes on a torus.
   Real involute teeth would read better in the scene 04 close-up.
2. **Discharge hood and feed chute** — currently extruded boxes; the real
   geometry in the photographs is more complex.
3. **Grating platforms** — an alpha-mapped tiled mesh instead of solid boxes.

None of these change what the presentation *says*. They are polish, and they
would each need to justify the asset pipeline they bring with them.

## 3. What actually produced the visuals

| Source | Used for |
|---|---|
| `assets/process/*.jpeg` | Proportions, materials, colour, wear, structural detail |
| `assets/dashboard/*.png` | The real Power BI report, unmodified |
| `web/public/data/*.json` | Every chart, every number, every trajectory |
| Procedural Three.js | All geometry |
| `RoomEnvironment` (three.js) | Image-based lighting, generated in memory |

Nothing in the shipped presentation was generated by an image or video model.
